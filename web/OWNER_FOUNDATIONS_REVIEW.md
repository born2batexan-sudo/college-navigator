## Access and accounting

`cycle-access.ts` requires a configured `ACCESS_CYCLE` (e.g., Fall 2027), existing non-demo household, signed-in administrator matching `DEMO_OWNER_EMAIL` and an owner auth link. Direct $0 grants require reason and idempotency key; complimentary/Founding Family invitations target a specific household, are hash-only, single-use and seven-day expiry, and require that household's signed-in owner to claim. A serialized/advisory-locked cap reserves no more than 25 distinct **lifetime combined** households, including invitations, even after revocation. No shareable/public grant link or client-supplied terms. Active access ends before August 1 following the named fall term and can be revoked; revocation does not erase accounting. Household deletion cascades access/invitations/assistant usage while de-identifying the household foreign key on financial orders and audit records; the cash ledger remains for reconciliation/retention review.

Orders, consideration/payment/refund/provider-fee/net-cash entries, and audit events are append-only/idempotent. One pending order per household-cycle is reused through a provider idempotency key; stale pending sessions need a reviewed expiration path. Stripe's pending order, verified payment and refunds reconcile in a signed, five-minute-tolerance raw-body webhook. Payment requires the configured server-only price identifier, expected cents, USD, paid status, matching household/cycle/order/session metadata, and a verified signature; redirect alone does nothing. Full refunds revoke paid entitlements. Fees are *pending* until a separately verified provider report is recorded by an owner through `reconcileProviderFee`; initial net cash is provisional and explicitly fee-pending. `reconciliationStatus` derives pending/reconciled/exception from entries rather than claiming a fee was known. Exceptions are retained in webhook events and summarized in owner UI. Final production work: review Stripe event semantics, retries, async and dispute/chargeback handling, provider fee import, checkout session expiration, staging verification of the existing product-access gate, and reporting.

Hosted Stripe Checkout may show Apple Pay/Google Pay when Stripe account, device, country and verified domain support them. There is **no direct wallet code**. Sign-in (Google/Apple/Microsoft or email magic link) is separate from payment and inbox access; provider buttons remain gated by `AUTH_PROVIDERS` and Supabase settings/callback allowlisting. No credentials were configured.

## Ask Campus Passage

`/ask` and `/api/ask` are gated by household product access **and** `ASSISTANT_ENABLED=1` (default off). The server rechecks household/student ownership and excludes demo/template data. Strict JSON input is byte-bounded; the UI is informational only while disabled. Requests containing private data, application/essay content, attestations/signatures, medical or financial disclosures, credentials, requests for submissions/payments/record changes, personalized decisions or prompt injection refuse. The lookup uses only the selected student's exact entering term and active tracked-school action rules; it rejects ambiguous matches and unsupported deadline/requirement/cost questions and requires current/applicable/high-confidence certified research, recent certification/rule/source verification, an HTTPS official source on an approved institutional domain, and no pending source change review. Unpublished, stale, unsupported, conflicting or absent evidence returns unknown. The final response is a **deterministic quotation with a source URL and term**; it never calculates a deadline, claims completion/eligibility or takes any action. Household and task state select evidence but are not used to invent claims. Connected mail is not answer evidence.

Optional `ASSISTANT_MODEL_ENABLED=1` uses the server-only `ANTHROPIC_API_KEY` via `lib/ask-provider.ts`. The fixed Claude Haiku adapter uses Anthropic Messages with JSON-schema output, an 8-second timeout, 128 max output tokens, one bounded quote, no retries, and validates the returned evidence ID and token accounting. The model may only select the already-vetted citation or abstain; it cannot write final prose. A timeout, malformed output, missing key, excessive cost, or abstention refuses rather than inventing an answer; disabled model mode falls back to the deterministic single-source quote. `assistant_usage` records household/actor, timestamp, evidence count, outcome code and conservative model cost, never question/answer text, chain of thought, student attributes or provider payload. Atomic household/day slot and 5-cent call reservation enforce 20 questions and a $1 daily model cap. Reservation is reconciled to conservative token-based cost after a successful provider call; provider failure keeps the reservation. Production activation still requires owner/security/privacy review, certified research freshness operations, provider key and structured-output staging verification, abuse/retention review, end-to-end access and cost tests, and explicit flag activation. **Do not enable or deploy as part of this change.**
