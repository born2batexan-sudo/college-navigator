# Net-new college first view (review-only; default OFF)

**Not certified, not launched.** A safe partial first view is the research objective, not 144 verified answers. **There is no 90–120-second end-to-end promise or measured SLA.** The legacy sequential worker is retired and percentage-only automated certification is quarantined. `process_requests.py` invokes `request_pipeline.py` and exits without claiming when `REQUEST_PIPELINE_ENABLED != 1`. The scheduled workflow is committed only as a default-off activation path; no scheduler, provider, migration, or live URL was exercised.

## Architecture

* `school_directory` UnitID + exact entering term uniquely identify shared public research; each `school_requests` row remains household-scoped and requires product access. No household mail, campus login, password, paywall, CAPTCHA, proxy, or protected essay content feeds research.
* Twelve parallel 12-subject lifecycle lanes use one shared official-domain-only public fetch/cache. Brave Search public index supplies discovery; HTTPS fetches reject private DNS/credentials/ports/redirects off-domain, respect robots.txt (fail closed), reject non-text/oversized/essay pages, and time out. Model outputs are **proposals**. Server-side evidence gate checks official URL, exact page substring and exact entering term; risky deadline/cost/requirement answers require independent corroboration, otherwise `under_review` or `conflicting`. Absence never proves non-applicability/publication timing. Each checkpoint gets one of nine explicit states; missing/timed-out lanes become `under_review`; a completed public search with no fetched pages becomes `not_found_official`.
* The worker's **105-second lane budget is only a per-attempt sub-budget**. It excludes five-minute cron polling (which GitHub may delay or skip), queue backlog, checkout/setup, claim/index calls, evidence persistence, report, and family page fetch/render. Its current 15-second HTTP read timeouts/retries can add substantial delay. No configured timing envelope can honestly guarantee a first view in 120 seconds. A single attempt has a queue reservation, a bounded provider meter, and ledger reconciliation. The worker now validates all 12 lane reservations against both its attempt ceiling and the server job estimate **before claiming**; unknown provider costs retain their reservation. Retries use attempt IDs/leases, and due `review` rows re-enter the queue by `next_check_at` without a notification. First-view status `review` means partial evidence, not automatically an owner exception; `failed` after bounded retries/unsafe conflicting states are exception triage. No automatic outbound owner messages are sent.
* **End-to-end deadline model:** measure UTC request persistence (`school_requests.created_at`) → first successful 144-state commit (`request_subject_states.last_checked_at` from the first attempt, captured externally before any recheck overwrites it) → authenticated family GET that returns those states, separately logging workflow scheduled/start/claim timing, queue depth, provider timing, evidence commit and report. A claimed worker budget or evidence commit alone is **not** family-visible latency. A default-off, post-commit GitHub workflow_dispatch wake-up is now built for new queued requests, while five-minute polling remains recovery. It uses a fixed workflow and server-only Actions-write credential scoped to the reviewed repository. An accepted dispatch is not a claim: GitHub startup/environment approval, concurrency and queue delay are unbounded. A wake-up failure does not undo persistence; a crash before dispatch relies on the poll. Until an operationally verified dispatcher with bounded queue wait exists and a real 60-school benchmark confirms the complete path, keep the first-view SLA unpromised. Stale/failed/partial states must remain labeled as such, never auto-certify.
* `request_subject_states` stores per-term states, safe source/quote only, fingerprints and last/next timestamps. A material fingerprint/revision changes only on evidence/state change, not on unchanged checks. `/request` displays status and official excerpts, never turns this shared first view into family action instances. Existing `/school` readiness is deliberately **not** granted by this pipeline.
